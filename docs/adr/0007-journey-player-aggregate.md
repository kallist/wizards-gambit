# 棋旅独立建模并纳入玩家完整存档

状态：accepted，已用于有限样章。2026-10-22。用户已确认Q7精编短局先行与Q8有限生活样章。当前验收见[交付记录](../planning/delivery-report-v12.md)。

棋旅有跨节点准备、一次重试、生活选择与归家记忆。将它塞进原普通棋局session会覆盖玩家尚未结束的经典／魔法棋；另开不归属账号的存储键则会绕过已有恢复、文件备份和云快照。

选择独立的journey领域状态与受控UI，通过所属PlayerStorage保存一个完整旅程聚合。一次命令在同一JSON值内提交节点、手牌、重试和已得记忆；本机同源写入使用同一scope锁和预期revision检查，过期命令拒绝并读回当前状态。页面私有临时会话复用相同适配器，不写原持久档。

完整PlayerSave内容升级到schema 3，明确包含journey；旧schema 2由解码器补空旅程，不丢旧章节、衣装、阅读、设置和棋局。文件及云快照沿用既有入口与不可变提交机制，不新增账号后端。导入仅采纳允许字段，棋旅中的棋局也必须经过共享验证和明确投影，不能顺带导出房间凭据或任意输入属性。

多设备合并保留本设备活跃旅程，永久记忆按稳定身份合并；另一设备的活跃旅程保留在可选快照中，须明确恢复，不把两段进行中的棋局拼接。新模式不改普通棋规、好友协议或固定试炼成绩。

杯垫仅有两种外观，按结局与递茶方向保留首次获得的图案及来历，最多18种模式；最近一晚另存lastMemory供自然回指。重复游玩不会不断扩大物品列表，也不覆盖首次来历。云端同一旅程较晚的结局不会自动关闭本地仍在进行的棋盘，其完整提交仍可在云快照中明确恢复。

代价是新增内容版本、迁移与并发测试；旧客户端不具备新旅程解释能力，不能承诺新旧客户端同时运行时无损。公开格式与验收说明须跟随实际实现更新。当前实现及其测试结果另记，不以本ADR声明已完成。
