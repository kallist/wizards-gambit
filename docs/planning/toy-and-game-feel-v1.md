# Toy 发布、排行榜与爽快演出

日期：2026-10-16

状态：DESIGN PROPOSAL v1。用户已确认魔法试炼最高分榜，并授权其余常规细节集中拟定。平台事实经过公开资料核验；游戏、SDK 适配、联网、榜单与发布均尚未实施。

## 已核验的平台事实

依据 [B站官方 Toy 介绍](https://www.bilibili.com/toy/publish/sdk/skill) 和 [官方维护的内容清单](https://github.com/bilibili/toy/blob/main/skills/toy/references/content-checklist.md)：

- Toy 接收网页构建产物，提供预览与审核发布流程；用户账号发布资格未核验。
- 内容位于 `/toy/<slug>/`，资源应走相对路径；入口 HTML 上限 1MB，整包限制以账号提示为准。
- 已有云存储与排行榜接口；排行榜提交保留个人最高分，同 Toy 玩家共享接口额度，适合结算时提交、打开榜单时读取。

这些能力已有官方资料依据，不代表本项目已经接入。官网 SDK/guide 的完整渲染正文尚未取得；身份、外部 HTTPS/WSS、多个独立榜、重置与服务端验分契约均未核实。官方没有在已读资料中明确禁止外连，也没有足够证据保证本项目的外连可用。

## 已确认的排行榜方向

首版在“人机模式”中提供一个“魔法试炼”入口，使用一套固定开局、AI 难度、牌池、抽牌种子与计分规则，记录最佳成绩。这样保留随机魔法的玩法，同时让同榜玩家面对可比较的挑战。

推荐积分围绕完成目标、有效战术与有限的回合效率奖励设计。重复击毁同一棋子、复活刷分和重复结算不能增加成绩。具体公式在试炼局面确定后写入规则表，不随客户端 UI 状态自行计算为最终事实。

剧情强调关系发展，同机和好友房间强调共同游玩，推荐不将这些局的胜场直接计入公共挑战榜。恋爱选项不改变排行榜成绩。

未选择的首版方向及其代价：

- 自由人机最高分：玩法自由，但随机手牌与 AI 难度不同会降低成绩可比性，需要明确分组或统一计分资格。
- 联网竞技段位：需要可信玩家身份、权威结果与可升可降的段位结算。现有最高分接口不能直接当作 Elo；需要进一步平台核验与后端设计。

不提前承诺日榜、赛季清零、多榜分组或完全防作弊。实现前核实 SDK 能力及信任模型；若只提供客户端分数接口，不能把基础合法性检查宣传为竞技级反作弊。

## 爽快感提案

爽快感来自明确因果：选择技能 → 看懂预览 → 施法破局 → 棋子击毁 → 新牌入手 → 马尔福的即时表情与回应。

### 操作反馈

- 点击棋子立刻显示可选格、攻击目标与取消方式。
- 技能选择显示作用范围和受影响棋子，让玩家在确认前理解收益。
- 对局动作先获得规则确认，再播放演出；联网等待有短提示，不能假装已经结算。
- 常规走棋保持利落，重要事件才使用较长演出。暂定常规移动约 250–400ms、普通击毁约 0.8–1.2s，属于设计目标，尚未测试。

### 击毁与施法

- 石雕棋子有明确起势、接触、破碎与收势，配合克制的命中停顿、碎片、金属/石材音色。
- 普通吃子、击毁后/车、解将、将军与终局有不同层次的反馈，避免所有动作都播放同一场长动画。
- 技能有可识别的形状语言：护盾环、飞来轨迹、石化蔓延、守护神轮廓和地形封锁。
- “技能后吃子”使用连续演出与战报记录，让连招产生实际反馈；不能凭特效多判一次击毁或奖励。
- 小型角色切入与表情变化在关键时刻强化反馈，后续可跳过或降低频率。

### 角色奖励

- 赢下关键局面时，马尔福从漫不经心转为认真，再嘴硬认可。
- 连招成功后，她可主动提出赌约或下一次约棋，哈利用直球把“棋局奖励”推进成约会。
- 成就与剧情解锁围绕约棋、共同复盘和关系回忆；角色内容按剧情节奏展开。
- 结算可保存带角色与原创短台词的战报图，便于玩家手动分享；是否接平台分享能力待 SDK 核验。

### 舒适模式与手机

- 2D 保留施法轨迹、棋子变化、音效、卡牌入手和完整角色互动。
- 舒适选项关闭运镜、震屏和强闪光，提供短动画与跳过；移动反馈保持清楚。
- 音频从用户交互后启用，独立控制音乐、效果与未来可能添加的配音。
- 手机优先棋盘可点与角色表情可读，长篇对话可以在回合间阅读；不能用特效遮住落点。

## Toy 架构边界与发布路线

- 前端以静态构建产物发布；角色图、模型与音频拆成资源文件并按需加载。
- 平台存档/榜单放在独立适配层，领域规则不依赖 Toy 全局对象。
- 普通浏览器开发环境的本地存档和演示榜标明本地性质；真实 Toy 读写另外验收。
- 好友房间采用外部权威服务的提案不变，但进入 Toy 的可用性必须经过 HTTPS/WSS 和真实预览验证。
- 排行榜、存档或外连失败应给出明确状态与重试入口；剧情与同机对局尽可能继续可玩。
- SDK 不向客户端提供任何自建服务器管理密钥；身份与成绩校验只使用核验过的接口契约。
- 保留主立绘的视觉质量，优先压缩非关键背景、按需加载 3D 和后续章节；最终预算依据账号包体提示和真机加载结果制定。
- 成品完成后先生成 Toy 预览，验证 B站网页与 App，再由用户审阅实际版本后决定提交审核。当前不登录、不申请资格、不提交发布。
