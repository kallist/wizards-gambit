## 当前验证边界

Toy构建、相对资源/本地字体、Worker实际走棋和SDK Mock榜单/存档流程已通过。上一轮三次Mock验证记录仍明确写有REAL TOY: NOT TESTED。本轮重新核对源代码与记录，并做下面的隔离覆盖复现，没有使用真实玩家浏览器、本机存档或真实Toy云数据。

官方文档页面依赖前端加载；本轮可下载官方SDK脚本并确认云存储/用户资料相关接口标识仍存在，这不证明登录、父容器RPC、数据归属、App WebGL/Worker/音频或移动端性能已经通过。真实Toy预览、登录与授权、杀后台恢复、账号切换、换设备、更新版本以及发布审核均未完成。当前Toy包未配置公开好友WSS服务，该模式会提示尚未开放。

## 已实现的保存范围

| 数据 | 本机自动保存 | 现有云备份 |
| --- | --- | --- |
| 章节解锁/位置、互动次数、试炼最高分 | 是 | 包含，但不是每次变化都上传 |
| 衣装拥有集合、心动 | 是 | 包含，但不是每次变化都上传 |
| 衣装领取去重记录 | 是 | 不包含 |
| 正在进行的非联网棋局 | 是 | 不包含 |
| 番外阅读位置与选择 | 是 | 不包含 |
| 穿着、2D/3D、舒适模式、配乐音量 | 是 | 不包含 |
| 好友房间重连身份 | 是 | 不包含；服务器房间也不是永久存档 |

来源：App.tsx的saveProgress、SESSION_KEY/SETTINGS_KEY写入，platform/companion.ts的mutate，outfitStories.ts的readDate/saveDate，以及platform/room.ts的重连凭据。本机存储正常且同源时的普通浏览器刷新恢复有自动化证据；不能据此外推B站App重装、清数据或跨设备恢复。

云对象是toy.ts的Progress，加上App.tsx的withCompanion生成的owned/heart。自动上传只在新衣装领取或章节完成等特定事件触发，另有设置中的手动备份。启动读取本机档，没有自动云恢复；云恢复需手动点击，恢复时对解锁数/互动次数/最高分/心动取较大值、衣装取并集。提交排行榜成绩是另一条接口，不等于完整进度云同步。

## 已复现的重要覆盖风险，尚未修复

1. 新设备没有先手动恢复云档，启动时只有初始本机进度。
2. 玩家完成章节或领到新衣装，触发自动syncProgress。
3. toy.ts直接setCloudStorage覆盖progress_v1；没有先读取并合并旧云档，也没有版本比较或全局写队列。

隔离内存SDK Mock复现结果：旧云档24套衣装、解锁6章；模拟未恢复的新设备首次奖励后上传3套衣装、解锁2章；再次读取得到3套、2章，旧云值被替换。**TESTED WITH MOCK；真实Toy中未实施这次覆盖，不声称真实玩家已经受损。**

复现脚本与结果保存在`.local/toy-save-audit/cloud-overwrite.mjs`和cloud-overwrite.json。它直接调用现有getCloudProgress/syncProgress，证明当前适配器在键值覆盖语义下没有保护已有更完整存档；它不是完整Toy设备生命周期测试。

其他边界：

- 云上传失败只有错误提示，没有持久待上传队列或联网后自动补传。恢复最多取回最后一次成功云备份中覆盖的数据；清理站点存储或换设备会失去云范围之外的本机记录。
- 所有云写直接覆盖同一key。当前“章节和奖励合并一次写入”只减少那一条旧/新双写风险，不保证手动/自动、多标签页、多设备之间不覆盖。
- 本机key没有B站账号命名空间，也没有账号切换处理。若平台在账号间沿用本机存储，存在串档及把上一账号本机进度合并/上传给下一账号的风险；真实Toy账号生命周期未验证。
- 本机衣柜有Web Locks协调；缺失时仅有模块内队列。这不构成跨设备云端事务保证。
