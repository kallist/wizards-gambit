## 2. 用户已明确的范围

- 参考《哈利·波特与魔法石》的巫师国际象棋。
- 有 3D 对局，也可以切换为适合晕 3D 玩家的平面 2D。
- 包含哈利·波特与金发傲娇的女性版本马尔福；后者为第一视觉主角，二次元立绘需兼具性感与可爱。
- 互动包含马尔福嘲讽、哈利直球、马尔福害羞，以及交往后的甜蜜情节。
- 魔法技能取材于电影或小说；技能种类要丰富。
- 双方三个技能，随机取得；击毁一个非兵单位可获得新技能。
- 剧情、人机、多人联网、同机双人四种模式。
- 电脑和手机操作都要考虑；所有 UI 都应精致、统一。
- 排行榜与爽快感纳入设计；发布目标为哔哩哔哩 Toy。

“双方三个技能”已确认为三个消耗型手牌槽。“技能强度概率相同”按共同牌池与同一抽取概率、相近强度目标拟定；精确平衡不应未经测试宣称完成。

## 3. 推荐产品方向

浏览器游戏，电脑与手机共用一套产品。体验核心是“会战斗的精致棋盘＋可读懂的魔法策略＋有进展的甜蜜关系”。

推荐保留两套规则预设：

1. 经典巫师棋：完整标准国际象棋规则、击毁演出，无技能。
2. 魔法技能棋：主要玩法，使用统一技能池、抽取与状态效果；规则需经访谈确认。

两种规则预设可以在适用的对局模式中选择。2D/3D 属于视图选择，不另算一种规则或玩法模式。

## 4. 魔法技能棋：已确认基础与集中评审细则

### 行动和胜负：基础已确认，边界待定

- 已确认以将死获胜、无血条、技能不能直接消灭国王；推荐不引入概率命中。
- 已确认一回合“可选施放一次技能，然后走一步棋”，允许跳过施法。技能对棋子与地形的改变仍然能影响威胁格与将军。
- 拟定允许使用技能解将或形成将军，施法后仍需完成正常走棋；在完整回合结算后判断胜负。国王不作为魔法直接选取目标，也不能通过魔法移动、复活或消灭。
- 施法目标确认前可取消；服务端确认施法后消耗技能并进入待走棋阶段，不允许撤销已公开的信息。确认施法前必须验证至少存在一个合法后续棋步，避免消费技能后进入无法完成的回合。
- 施法中可暂时保留既有将军，但完整回合结束时本方国王必须安全；王车易位仍不得穿越受攻击格。双方王不能因位移效果变成非法相邻。
- 持续效果统一采用清楚的到期节点，优先限制到对方下一回合结束；判定本方回合合法性时也检查该回合末将失效的效果。UI 标出“失效后会暴露国王”的落点，避免保护到期造成不明原因的非法局面。
- 回合阶段、施法记录、已消耗手牌和局面版本进入权威状态，断线重连回到原阶段。动画不决定结算。
- 判定将死时必须考虑合法技能解围，不能先用普通棋规则判死、再外挂技能。
- 经典预设完整保留标准棋规则。魔法预设保留标准易位、吃过路兵与四种升变，并明确技能位移对相关权利的影响；不得通过直接改棋盘保留已经失效的易位资格。
- 魔法预设的重复局面依据完整规则状态，而非仅棋子位置；无进展计数考虑实际兵移动与击毁。自动子力不足和棋只在没有手牌和持续效果影响时沿用标准判定，其余局面使用逼和、重复、无进展上限与双方同意和棋。

### 抽取与补充：手牌循环已确认，其余为拟定细节

- 已确认开局取得三张一次性技能牌、持有上限三张；拟定从共同技能池等概率抽取，同一手牌不重复，双方可以拥有相同技能。
- “等概率”指双方使用同一抽取规则，没有隐藏稀有度、付费权重或角色抽卡加成。不等同于双方每局获得相同技能。
- 初始候选池目标为 24 种。后续从排除本方当前已持有牌的候选集等概率抽取；已用掉的牌以后允许再次抽到。规则公开这一条件概率，不设置隐藏权重。
- 使用后消耗。击毁对方车、马、象、后时补一张；已确认满手先取得新牌，再在四张中选择保留三张，结算期间不能继续行动。
- 已确认新牌下一回合才能使用，避免一回合连锁刷牌。
- 已确认按棋子唯一身份记录奖励资格：同一枚棋子本局最多产生一次补牌；复活不重置资格。
- 已确认对手手牌不可见，施放时公开；同机交接期间遮挡手牌。
- 拟定升变本身不补牌；升变后的棋子被击毁时按当前车/马/象/后种类获得一次奖励，同一实体仍受一次资格约束。
- 首批技能不直接移除棋子；击毁由正常吃子产生。恢复类技能仅恢复符合条件的兵，保留原身份和既有奖励状态。
- 初始残局为每枚棋子与可恢复棋子分配稳定身份。候选集不足三张时只抽取实际可用数量并明确提示；正式完整牌池不应出现这一情况。
- 若吃子已结束对局，补牌展示不阻塞终局，也不要求玩家继续进行满手取舍。

### 强度目标

- 所有技能以相近的行动价值为目标，通过目标范围、持续时间、使用时机和反制条件调整。
- 不宣称 24 种技能天然等强。等概率可通过代码与记录验证；平衡还需要局面测试、自动对弈与真人体验。
- 避免无条件删除后、连续行动、无限复活、永久冻结，以及纯粹通过隐藏按钮或改变点击方式制造困难。
- 剧情中的喜欢程度与对话选项不改变联网技能强度。

## 5. 24 个候选技能方向

以下为游戏改编提案，不是原作巫师棋已有技能。每项最终必须补齐原作出处、目标、时机、持续时间、棋王安全约束、反制与交互预览；未完成的项目不进入正式技能池。

| 类别 | 原型 | 候选战术作用 |
| --- | --- | --- |
| 机动 | 羽加迪姆勒维奥萨 / Wingardium Leviosa | 一次限定的越障走位；不直接增加吃子次数 |
| 机动 | 飞来咒 / Accio | 将一个己方非王棋子拉向指定的合法空格，限距离 |
| 机动 | 滑道平平 / Glisseo | 在指定直线路径获得一次受限滑行 |
| 机动 | Waddiwasi | 将己方小型棋子弹到相邻空格，制造不同于拉取的位移 |
| 防御 | 盔甲护身 / Protego | 为一枚棋子阻挡一次指定类型的敌方魔法 |
| 防御 | 呼神护卫 / Expecto Patronum | 小范围、短时间保护；用更严条件控制范围收益 |
| 防御 | 咒立停 / Finite Incantatem | 移除一枚棋子的可解除负面魔法状态 |
| 防御 | 恢复如初 / Reparo | 有限召回一个已击毁的兵；不产生重复补牌资格 |
| 控制 | 统统石化 / Petrificus Totalus | 暂时限制一枚棋子的移动；攻击范围如何改变需定稿 |
| 控制 | 障碍重重 / Impedimenta | 暂时缩短一枚长程棋子的移动距离 |
| 控制 | 昏昏倒地 / Stupefy | 对低价值目标施加短暂吃子限制，保留明确反制 |
| 控制 | 塔朗泰拉舞 / Tarantallegra | 强制目标改变落点意图，目标方从安全候选中选择 |
| 地形 | 火焰熊熊 / Incendio | 在少量空格放置短期火焰区域，限制路线 |
| 地形 | 清水如泉 / Aguamenti | 清除火焰并产生受限水流走位效果 |
| 地形 | 快快禁锢 / Colloportus | 封锁一个受限制空格，短时间改变通路 |
| 地形 | 阿拉霍洞开 / Alohomora | 打开一段魔法封锁，并给予一次限定通行机会 |
| 破局 | 除你武器 / Expelliarmus | 对非王棋子施加一次受限退却，目标与价值有限制 |
| 破局 | 四分五裂 / Diffindo | 切断一个魔法屏障或保护效果，不直接删除棋子 |
| 破局 | 速速变大 / Engorgio | 临时扩展一个兵的威胁范围；不改变永久棋种 |
| 破局 | 速速缩小 / Reducio | 给己方棋子受限穿隙能力；不允许重叠占格 |
| 诡计 | 荧光闪烁 / Lumos | 揭示一张对方技能，若手牌最终公开则需改设计 |
| 诡计 | 诺克斯 / Nox | 给一枚棋子短暂的魔法选取保护，不隐藏实际棋盘位置 |
| 诡计 | 一忘皆空 / Obliviate | 置换一张对方技能，对称抽取规则与范围待定 |
| 诡计 | 滑稽滑稽 / Riddikulus | 将一类控制魔法化解为喜剧演出，定义专门反制窗口 |

控制类之间必须有实际不同的决策价值，不能只换名称。所有位移、封锁、保护、攻击范围改变都须由规则层评估合法性；技能不能使双方棋王处于非法相邻状态。

## 6. 剧情与互动

### 推荐关系线

已确认成年后重返霍格沃茨的冬季同人 AU，从互怼、暧昧、告白写到已经交往后的日常。第一部主要作为棋室、石雕棋子与击毁演出的参考，时间线不绑在第一学年。

六章建议：

1. 《波特，你连棋都不会？》：嘴硬教学；合法移动、吃子与第一次直球。
2. 《输的人负责黄油啤酒》：棋局赌约；首次使用技能，她开始认真记住他的习惯。
3. 《只是顺手替你挡一下》：防御与牺牲残局；关心从嘴硬里漏出来。
4. 《圣诞夜禁止认输》：雪夜双人练棋；一次明确的告白，关系正式推进。
5. 《现在可以叫我名字了》：交往后的小约会、换围巾、坐到同一侧研究残局。
6. 《这次，换我们并肩》：合作剧情残局，共同迎战被施咒的棋盘；结尾回到双人夜棋。

拟定故事主要由玩家以哈利视角体验；自由对局可选择角色与颜色。剧情失败允许重试，重复失败可开启提示或降低电脑难度继续；保留安慰与照顾的互动，不把恋爱进度绑定全胜。

### 内容目标

- 初步内容预算：六章、约 120 组情境对话、约 12 段较完整的甜蜜场景。是规划数量，不是现成内容。
- “一组情境对话”是一段带触发条件的短交流，不按单个气泡重复计数。
- 按关系阶段安排语气：初见称“波特”；暧昧时口是心非；交往后敢于表达关心，不让她永远只会脸红否认。
- 马尔福保留骄傲、棋力、判断和主动性；哈利真诚直接，也会认真听她的建议。
- 触发来源包括开局、关键吃子、漂亮防守、错误、反败为胜、特殊技能、告白后重访与输棋安慰。
- 重复抑制、情境优先级、关系阶段隔离、跳过、历史回看与静音分别处理。联网中剧情呈现不阻塞对方时钟。
- 不依赖运行时 LLM 生成对白，避免不稳定的人设、费用和联网等待。
- 首版拟定字幕、表情、音效与有明确来源的音乐。完整角色配音不作为当前承诺；对白和演出保留后续扩展空间。

示例原创交流：

> 马尔福：“你盯着我做什么，波特？棋盘在下面。”
>
> 哈利：“因为你笑起来比赢棋更让我高兴。”
>
> 马尔福：“……那你最好快点赢，我可没答应陪你坐一整晚。”

交往后的一段：

> 马尔福把热杯子推到哈利手边：“下一局认真点。赢了我，才有奖励。”
>
> 哈利：“奖励是明天也和你约会吗？”
>
> 她移开视线：“明天本来就给你留了。别把茶放凉。”

## 7. 四种模式

| 模式 | 核心体验 | 首轮推荐范围 | 需要另行决定 |
| --- | --- | --- | --- |
| 剧情 | 章节、残局、关系推进 | 六章线性主线，甜蜜结局与可回看互动 | 分支多少、主控角色、故事时间线 |
| 人机 | 可重复的自由对局与魔法试炼 | 三档难度，电脑理解技能、允许经典预设；固定试炼最高分榜 | 实测思考时长与棋力 |
| 联网 | 不同设备的真实对战 | 好友房间码、选边、准备、重连、再来一局 | Toy 外连能力与真实部署 |
| 同机双人 | 一台设备轮流玩 | 回合交接遮罩，隐藏待接手玩家的技能，确认后继续 | 是否计时、双方是否允许看对方手牌 |

多人联网首版已确认采用 1v1 好友房间，不加入公开匹配。独立账号体系、联网竞技段位榜、观战与聊天不纳入首版；用户已确认的魔法试炼最高分榜属于首版范围。

首版好友房间拟定默认不计时，短暂掉线保留座位并提供五分钟重连宽限；过期房间可关闭。房间状态先采用有界内存保存，服务器重启不承诺恢复，不能宣传为持久对局服务。若平台接入要求另有变化，单独报告。

## 8. 审美与界面

### 视觉提案

- 主场景：哥特拱窗、烛光、雪夜、磨损石材；棋盘和棋子是视觉焦点。
- 配色提案：黑曜石底色、暖象牙白、旧金边饰、深祖母绿；红金与绿银用于角色阵营识别。
- 角色：女性版本马尔福是首要视觉主角。以流行二创的铂金发、贵族气、绿银服饰、耳饰、挑眉坏笑和害羞反差作为参考，制作成年角色的二次元游戏立绘，兼顾性感与可爱。具体美术见 `art-direction.md`。
- 棋子：可以一眼识别的石雕兵、骑士、塔楼、主教、王后与国王。击毁有重量与碎片，平时克制。
- 中文标题采用适量的衬线感字形，正文与规则采用清晰中文无衬线；具体字体许可和性能在实现时验证。

### 页面与操作

- 主页：以马尔福大幅角色立绘为主视觉，棋室作为环境，配四个模式入口、继续剧情、设置。不要用营销落地页的重复 CTA、评价区填充游戏主页。
- 对局：中央棋盘最大；角色区域和技能手牌让位于棋盘；常驻回合、将军提醒、2D/3D 切换与设置。
- 技能：图标、名称、一句效果、适用目标。选择后显示预览与取消，目标非法时说明原因，确认前不消耗。
- 手机版：棋盘占据主要宽度，技能托盘与角色对白可收起；手指点击选择棋子再点目标，不能只依靠拖拽或悬停。
- 交接页：清楚显示“请交给另一位玩家”，遮挡手牌，明确确认进入。
- 结算：结果、关键事件、剧情互动、重试/再来一局；不能把输棋做成羞辱式反馈。
- 空房间、等待对手、连接中、掉线、重连失败、资源加载失败都需要完整样式与可用操作。
- 对比度、键盘焦点、可读状态标识、至少 44px 的主要触控按钮、音量分类与文本大小纳入验收。

### 2D 与舒适选项

- 真正的平面 SVG/DOM 棋盘，不只是把 3D 镜头拉高。
- 同步显示棋子、合法落点、技能效果、最近一步与棋盘坐标。
- 任意未完成交互中的切换须保留一致状态，不能重开、重新抽牌或重播剧情。
- 关闭镜头旋转、自动运镜、景深与震屏；简化碎片与闪光，支持跳过击毁动画。
- 尊重 prefers-reduced-motion；2D 模式无需加载完整 3D 场景，3D 不可用时提供 2D。
- 视图方向可单独翻转；同机交接不强制执行令人眩晕的镜头旋转。

## 9. 技术架构提案

当前没有现有项目，以下是拟选架构，并非已存在的代码结构。

- TypeScript 共享领域规则：完整棋局、技能、合法动作、胜负、抽取与可复现事件。纯逻辑不依赖 UI 或 3D。
- React + Vite 浏览器界面；Three.js 3D；SVG/DOM 2D。选择这些方案是为跨设备操作和共享状态，不引入原生 App 打包。
- AI 在 Worker 中搜索同一组合法动作，限制时间与分支数量；难度不通过偷看隐藏手牌实现。
- Node + WebSocket 好友房间服务。服务端维护权威棋局，客户端发送动作请求；前端私自修改的局面不能成为事实。
- 联网动作校验座位权限、回合、局面版本、目标与请求编号，串行结算，重复请求不重复抽牌或走棋。
- 联网随机抽取由服务端处理；客户端只收到有权看到的手牌。房间码是加入方式，不是重连凭证。
- 事件先结算再演出，棋子动画和对白不负责修改规则。网络结果、AI、2D 与 3D 都使用同一裁决。
- 本地剧情存档使用有版本的存档结构，包含关系阶段与完整魔法状态；不只存 FEN。
- 首版拟定有界内存房间与短期重连，不新增持久对局数据库；服务器重启不承诺恢复。
- Toy 适配层与规则分离，接入平台存档和榜单；通用浏览器开发环境提供明确的本地适配，不能将本地榜单当作 Toy 全球榜。
- Toy 内置排行榜已有官方资料依据。好友房间仍需外部权威服务，Toy 的外连和 App 内兼容性需要实际验证。

拟涉及目录：`src/domain/`、`src/ai/`、`src/ui/`、`src/renderers/`、`src/story/`、`server/`、`tests/`。实际结构在实施前确定。

标准 chess.js 只覆盖普通棋规则，且不提供 AI。其能否作为本项目局部基础，要等技能规则确定后评估；不能用绕过校验或直接改棋盘的方式伪造合法魔法动作。

## 10. 实现顺序、风险与验证

推荐顺序，不削减最终四模式范围：

0. 先确定马尔福角色主立绘、表情对照与主菜单/对局页面的构图，验证最重要的角色吸引力；当前仅为计划，尚未生成素材。
1. 规则定稿与可测试核心：经典规则、自定义合法动作、三技能手牌、补牌、状态生命周期。
2. 可玩的同机双人和 2D 视图，证明完整对局可以正确结束。
3. 同一局面的 3D 呈现、棋子击毁与技能演出、舒适选项。
4. 技能 AI、剧情第一章与关系触发，再扩展到全部章节和通过检查的技能池。
5. 真实好友联网、重连和安全校验；手机与电脑界面统一打磨。
6. Toy SDK 适配、真实预览和 B站 App 验证、封面和包体检查；发布提交安排在成品审核之后。

主要风险：自定义规则组合爆炸、技能强度不平衡、补牌滚雪球、AI 分支过多、移动端 3D 性能、角色与棋子素材的一致性、联网状态泄露与重连同步。

验证计划：

- 棋类规则：易位、吃过路兵、升变、将军、将死、逼和、重复局面与魔法解围。
- 每个技能：合法目标、非法目标、失效时机、反制、王安全及与持续效果的组合。
- 补牌：兵不触发、普通高阶子触发、满手选择、重复请求、复活再次击毁、升变和新牌可用时机。
- 随机：合法候选集、双方相同规则、可重现记录；统计观察只作为辅助，不能证明平衡。
- 视图：2D/3D 切换前后完整规则状态相同，不重新抽牌；3D 加载失败可继续 2D。
- AI：不非法走棋、正确处理技能解围、不读取对方隐藏信息、超时安全回退。
- 剧情：阶段前后不串台、重复抑制、失败重试、跳过和存档恢复。
- 联网：跨设备、过期局面、重复发送、越权座位、非法技能、断线重连、隐藏手牌；真实跨网络实测单独记录。
- UI：桌面和移动端布局、触控、键盘、低动态模式、错误态与载入态；使用实际浏览器截图验收。
- 排行榜：真实平台成绩提交、排名读取、重复提交、失败反馈与限流处理；本地演示榜与真实 Toy 榜分开记录。
- 完成阶段运行类型检查、相关单元/集成测试、构建、浏览器端到端测试与差异自查。Docker 和 Hosted CI 是否为交付门槛需另定。

当前测试结果：NOT TESTED；当前提交、分支、PR、部署：不存在。此阶段只创建设计文档。

当前 API/DB 变更：无；未添加依赖、凭据、运行时模型调用或对外服务。
